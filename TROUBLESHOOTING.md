# Dépannage

Commencer par `codexbridge doctor`, puis `codexbridge job CB-n` et `codexbridge report CB-n`. Les erreurs et commandes du job sont dans son activité dashboard et `get_job_events`. Les erreurs serveur sont sous `.codexbridge/logs`.

| Symptôme                                 | Vérification et action                                                                                                                                                                                                                              |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex not found / ENOENT                 | Installer le CLI officiel ou renseigner `codexCommand` avec le chemin absolu du binaire. Sous Windows, utiliser `codex.exe`, pas un `.cmd`.                                                                                                         |
| Authentication failure                   | Dans le même compte OS et environnement que le service, lancer `codex login`, puis `codex login status`. Ne pas copier de token dans le ticket.                                                                                                     |
| OpenAI API error                         | Vérifier `reviewer`, `reviewerModel`, la clé locale, le quota et le réseau. Les codes HTTP sont conservés sans exposer la clé. Retry après correction ; le thread worker est conservé.                                                              |
| MCP unavailable                          | Démarrer le service ; vérifier `/health`, le token et `CODEXBRIDGE_HOME`. Pour le cloud, vérifier le tunnel ou HTTPS/OAuth. Une URL localhost ne suffit pas.                                                                                        |
| Port already used                        | Fermer l’autre service ou changer `port` et mettre à jour le client MCP. Un second scheduler ne doit pas être lancé sur la même DB.                                                                                                                 |
| SQLite lock                              | Vérifier qu’aucun autre service n’utilise la DB ; délai busy de 5 s. Stocker SQLite sur disque local, pas sur partage réseau/OneDrive. Sauvegarder avant toute réparation.                                                                          |
| Invalid repository                       | Utiliser un root Git absolu existant, autorisé dans `repositoryRoots`, avec au moins un commit.                                                                                                                                                     |
| Worktree corruption / branche différente | Le job échoue sans supprimer les données. Examiner `git worktree list`, la branche attendue et le rapport ; réparer explicitement, puis retry. Ne pas réassigner un job à un worktree quelconque.                                                   |
| Merge conflict                           | Le service ne fusionne pas. Un conflit présent dans le worktree est à résoudre dans ce worktree ; envoyer une instruction précise.                                                                                                                  |
| Job stuck / timeout                      | Lire les derniers événements. Annuler interrompt le passage et préserve le travail. Vérifier le PID enregistré ; retry est bloqué tant qu’il vit. Ne jamais tuer un PID sans vérifier le processus.                                                 |
| Review loop                              | Lire les reviews. Après le budget maximal, FAILED préserve tout. Retry avec contexte supplémentaire autorise jusqu’à cinq passages de plus.                                                                                                         |
| Structured output invalid                | Le passage échoue explicitement ; mettre à jour/vérifier la compatibilité du CLI et relancer le même job.                                                                                                                                           |
| Permission / sandbox / PowerShell        | La demande d’élévation n’est pas acceptée automatiquement. Corriger la configuration locale ou proposer une alternative. Sous Windows, une configuration PowerShell située dans OneDrive peut être indisponible si le fournisseur cloud est arrêté. |
| Connexion perdue / crash                 | Voir [recovery](docs/RECOVERY.md). Un job interrompu n’est jamais validé arbitrairement.                                                                                                                                                            |

Pour un service démarré depuis un autre répertoire, définir `CODEXBRIDGE_HOME` en chemin absolu. Une configuration différente signifie une autre DB et un autre token. `doctor` distingue un service arrêté d’une authentification indisponible ; il ne prétend pas avoir vérifié l’API distante simplement parce qu’une clé existe.
